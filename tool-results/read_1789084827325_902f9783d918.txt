    28→## 1. 에이전트 개요
    29→
    30→### 1.1 역할 정의
    31→
    32→대시보드 개발에 투입되는 에이전트와 역할을 정의한다. 기본 에이전트 설정의 역할을 계승하며, 대시보드 특성에 맞게 역할 범위를 한정한다.
    33→
    34→| 에이전트 | 역할 | 기술 | 대시보드 담당 영역 |
    35→|---|---|---|---|
    36→| **개발 에이전트** | 관리자 UI + API 전체 구현 | full-stack-developer | Prisma schema, Admin API Routes, Admin UI 컴포넌트, JWT/RBAC, CMS CRUD, 통계/감사 로그 |
    37→| **스타일링 에이전트** | 반응형 관리자 레이아웃, 차트 스타일링 | frontend-styling-expert | 21"/24" 데스크톱, 태블릿(768px), 모바일(375px) 반응형, recharts 테마, shadcn/ui 커스터마이징 |
    38→| **브라우저 에이전트** | 대시보드 E2E 검증 | agent-browser | 로그인 플로우, CMS 편집→키오스크 반영, RBAC 권한 차단, 반응형 레이아웃 스냅샷 |
    39→
    40→### 1.2 에이전트 책임 매트릭스
    41→
    42→```
    43→                        개발      스타일링    브라우저
    44→                        에이전트   에이전트    에이전트
    45→─────────────────────────────────────────────────────────
    46→Prisma 스키마 설계        ●         ○         ○
    47→DB 마이그레이션           ●         ○         ○
    48→Admin API Route          ●         ○         ○
    49→JWT 인증 구현            ●         ○         ○
    50→RBAC 권한 체계           ●         ○         ○
    51→Admin UI 컴포넌트        ●         △         ○
    52→shadcn/ui 커스터마이징    △         ●         ○
    53→반응형 레이아웃          △         ●         △
    54→recharts 차트 스타일      ○         ●         ○
    55→CMS 편집 인터페이스      ●         △         ○
    56→이미지 업로드             ●         ○         ○
    57→통계 대시보드             ●         △         ○
    58→감사 로그 UI             ●         △         ○
    59→E2E 로그인 플로우        ○         ○         ●
    60→E2E CMS→키오스크 반영    ○         ○         ●
    61→E2E RBAC 차단 확인       ○         ○         ●
    62→반응형 스냅샷 검증       ○         ○         ●
    63→
    64→● = 주 담당   △ = 협업   ○ = 미참여
    65→```
    66→
    67→### 1.3 에이전트 간 통신 규칙
    68→
    69→```
    70→1. 개발 에이전트가 API 구현 완료 → 브라우저 에이전트에 E2E 검증 요청
    71→2. 개발 에이전트가 UI 컴포넌트 작성 완료 → 스타일링 에이전트에 반응형 조정 요청
    72→3. 스타일링 에이전트 조정 완료 → 브라우저 에이전트에 반응형 스냅샷 검증 요청
    73→4. 브라우저 에이전트 오류 발견 → 개발 에이전트에 수정 요청 (워크로그에 기록)
    74→5. 모든 에이전트는 worklog.md를 통해 비동기적으로 상태 공유
    75→```

   188→### 2.2 Phase 간 병렬 실행 전략
   189→
   190→Phase 내에서 독립적인 작업은 병렬로 실행한다:
   191→
   192→```
   193→Phase 1 (직렬):
   194→  └── 스키마 작성 → 마이그레이션 → 시드 (순차 의존)
   195→
   196→Phase 2 (병렬 그룹 A):
   197→  ├── JWT/RBAC 미들웨어 구현
   198→  └── Admin API 인증 엔드포인트 구현
   199→
   200→Phase 2 (병렬 그룹 B, A 완료 후):
   201→  ├── 로그인 페이지 UI 작성
   202→  └── AdminLayout 컴포넌트 작성
   203→
   204→Phase 3 (병렬 그룹 A):
   205→  ├── /api/admin/cms CRUD 구현
   206→  └── /api/cms (공개) 구현
   207→
   208→Phase 3 (병렬 그룹 B, A 완료 후):
   209→  ├── useCmsContent() 훅 작성
   210→  └── Polling/ETag 로직 구현
   211→
   212→Phase 4 (병렬 — 페이지 간 독립):
   213→  ├── /admin 대시보드 홈
   214→  ├── /admin/cms 콘텐츠 관리
   215→  ├── /admin/books 도서 관리
   216→  ├── /admin/users 사용자 관리
   217→  ├── /admin/notices 공지 관리
   218→  └── /admin/settings 시스템 설정
   219→
   220→Phase 5 (직렬):
   221→  └── 업로드 API → 프리뷰 UI → 에러 처리
   222→
   223→Phase 6 (병렬 그룹 A):
   224→  ├── 통계 API + 차트 컴포넌트
   225→  └── 감사 로그 API + UI
   226→
   227→Phase 7 (직렬 — 순차 검증):
   228→  └── 로그인 → CMS → RBAC → 반응형 → 업로드 → 감사 로그
   229→```

   231→### 2.3 Phase 전환 조건
   232→
   233→| 현재 Phase | 완료 조건 | 다음 Phase |
   234→|---|---|---|
   235→| Phase 1 | `npx prisma migrate dev` 성공, 시드 데이터 조회 확인 | Phase 2 |

   240→| Phase 6 | 통계 차트 렌더링, 감사 로그 자동 기록 확인 | Phase 7 |
   241→| Phase 7 | 모든 E2E 검증 통과 | **완료** |

   245→## 3. 작업 추적
   246→
   247→### 3.1 Todo 시스템 — 대시보드 확장
   248→
   249→기본 에이전트 설정의 Todo 시스템을 계승하며, 대시보드 Phase 기반 Task ID 체계를 사용한다.
   250→
   251→```typescript
   252→interface DashboardTodo {
   253→  id: string;           // "{phase}-{seq}" 형식
   254→                       // 예: "1-1" (Phase 1, 작업 1)
   255→                       //     "2-a" (Phase 2, 병렬 A)
   256→                       //     "2-b" (Phase 2, 병렬 B)
   257→                       //     "4-3" (Phase 4, 페이지 3)
   258→  content: string;      // 작업 설명 (한국어)
   259→  status: 'pending' | 'in_progress' | 'completed';
   260→  priority: 'high' | 'medium' | 'low';
   261→  phase: 1 | 2 | 3 | 4 | 5 | 6 | 7;  // 대시보드 Phase 번호
   262→  agent: 'dev' | 'style' | 'browser';  // 담당 에이전트
   263→  blocks?: string[];    // 차단하는 후속 Task ID 목록
   264→  blockedBy?: string[]; // 선행 Task ID 목록
   265→}
   266→```

   350→### 4.1 공통 지침 (대시보드 모든 서브에이전트)
   351→
   352→기본 에이전트 설정의 공통 지침(`6.1`)을 모두 계승. 추가 지침:
   353→

   355→1. Admin API Route는 반드시 /api/admin/* 경로에 위치

   560→|---|---|---|---|
   561→| **JWT token expired** | JWT 만료 (기본 8시간) | 1. `/api/admin/auth/login` 재호출로 갱신<br>2. 클라이언트에서 401 감지 시 자동 리다이렉트<br>3. JWT_EXPIRES_IN 환경변수 확인 | 개발 |
   562→| **RBAC permission denied** | 역할에 권한 없음 | 1. AdminRole.permissions 필드 확인<br>2. withAdminAuth의 requiredPermission 파라미터 확인<br>3. super_admin으로 로그인 후 권한 재확인 | 개발 |
   563→| **CMS content not reflecting** | 키오스크에 변경 미반영 | 1. Polling 인터벌 확인 (기본 30초)<br>2. ETag 응답 헤더 확인 (304 vs 200)<br>3. /api/cms 응답 데이터 확인<br>4. useCmsContent() 훅 마운트 상태 확인<br>5. 브라우저 캐시 강제 갱신 (Ctrl+Shift+R) | 개발 |
   564→| **Image upload fail — file size** | 파일 크기 초과 (최대 5MB) | 1. 클라이언트에서 파일 크기 사전 검증<br>2. MAX_UPLOAD_SIZE 환경변수 확인<br>3. 서버에서 Content-Length 확인 | 개발 |
   565→| **Image upload fail — MIME type** | 허용되지 않은 파일 형식 | 1. ALLOWED_MIME_TYPES 확인 (image/jpeg, image/png, image/webp, image/svg+xml)<br>2. 파일 확장자와 실제 MIME 일치 확인 | 개발 |
   566→| **Audit log missing** | withAuditLog 래퍼 미적용 | 1. mutation 핸들러에 withAuditLog 적용 여부 확인<br>2. withAuditLog 내부에서 트랜잭션 롤백 시 AuditLog도 롤백되는지 확인<br>3. prisma.auditLog.create 호출 확인 | 개발 |
   567→| **Admin page blank** | 인증 미완료 또는 컴포넌트 오류 | 1. JWT localStorage 존재 확인<br>2. 브라우저 콘솔 React 에러 확인<br>3. AdminLayout 렌더링 조건 확인 | 개발 |
   568→| **Sidebar navigation broken** | RBAC 필터링 오류 | 1. 사용자 역할의 permissions 확인<br>2. 메뉴 항목의 requiredPermission 확인<br>3. AdminLayout 내 네비게이션 필터 로직 확인 | 개발 |
   569→| **Chart not rendering** | recharts 데이터 형식 오류 | 1. API 응답 데이터 구조 확인<br>2. recharts 컴포넌트 data prop 형식 확인<br>3. ResponsiveContainer 높이 설정 확인<br>4. 데이터 빈 배열 시 빈 상태 UI 확인 | 스타일링 |
   570→| **Responsive layout broken** | 브레이크포인트 누락 | 1. Tailwind 반응형 클래스(sm/md/lg/xl/2xl) 확인<br>2. 지정 너비(375/768/1024/1920)에서 렌더링 확인<br>3. AdminLayout 사이드바 상태 확인 | 스타일링 |
   571→
   572→### 5.2 인증/인가 디버깅 순서
   573→
   574→```
   575→1. 브라우저 localStorage에서 JWT 존재 확인
   576→   localStorage.getItem('admin_token')

   580→   JSON.parse(atob(token.split('.')[1]))
   581→
   582→3. /api/admin/auth/me 호출로 토큰 유효성 확인
   583→   curl -H "Authorization: Bearer {token}" http://localhost:3000/api/admin/auth/me
   584→
   585→4. AdminUser 레코드 확인
   586→   npx prisma studio → AdminUser 테이블
   587→
   588→5. AdminRole.permissions 확인
   589→   npx prisma studio → AdminRole 테이블
   590→
   591→6. withAdminAuth 미들웨어 동작 확인
   592→   - 콘솔에 디버그 로그 추가
   593→   - requiredPermission 파라미터 확인
   594→```

   596→### 5.3 CMS 동기화 디버깅 순서
   597→
   598→```
   599→1. 관리자 대시보드에서 CMS 편집 → 저장 성공 확인

   601→2. /api/cms 엔드포인트 직접 호출로 데이터 확인
   602→   curl http://localhost:3000/api/cms
   603→
   604→3. ETag 응답 헤더 확인
   605→   curl -I http://localhost:3000/api/cms
   606→   # ETag: "..." 헤더 존재 확인
   607→
   608→4. 조건부 요청 (If-None-Match) 테스트
   609→   curl -H "If-None-Match: {etag}" http://localhost:3000/api/cms
   610→   # 304 Not Modified 응답 확인
   611→
   612→5. useCmsContent() 훅 폴링 동작 확인
   613→   - 브라우저 Network 탭에서 /api/cms 요청 간격 확인
   614→   - 기본 인터벌: 30초 (KioskSetting에서 설정 가능)
   615→
   616→6. 키오스크 화면에서 변경 내용 반영 확인
   617→   - 강제 갱신: /api/cms?nocache=1
   618→   - 키오스크 컴포넌트 remount: 화면 전환 후 복귀
   619→```

   622→
   623→```

   625→   curl -H "Authorization: Bearer {token}" \
   626→     http://localhost:3000/api/admin/audit-log?limit=10
   627→

   661→## 6. 배포 체크리스트
   662→
   663→### 6.1 대시보드 릴리즈 전 확인
   664→
   665→```markdown
   666→□ 1. Admin 시드 데이터 생성
   667→     - AdminUser: super_admin 1명, admin 1명, viewer 1명
   668→     - AdminRole: 3개 역할과 권한 매핑
   669→     - 시드 스크립트: npx tsx prisma/seed-admin.ts
   670→
   671→□ 2. CMS 기본값 DB 마이그레이션
   672→     - CmsContent: 모든 화면 키별 기본값 INSERT
   673→     - KioskSetting: polling 인터벌, 기본 설정값
   674→     - 시드 스크립트: npx tsx prisma/seed-cms.ts
   675→
   676→□ 3. JWT Secret 환경변수 설정
   677→     - JWT_SECRET: 32자 이상 랜덤 문자열
   678→     - JWT_EXPIRES_IN: "8h" (운영 환경)
   679→     - .env.production에 설정 확인
   680→
   681→□ 4. Admin 로그인 동작 확인
   682→     - /admin → 로그인 페이지 리다이렉트
   683→     - 올바른 자격증명 → 대시보드 홈 리다이렉트
   684→     - 잘못된 자격증명 → 에러 메시지 표시
   685→     - 로그아웃 → 로그인 페이지 리다이렉트
   686→
   687→□ 5. CMS 편집 → 키오스크 반영 확인
   688→     - /admin/cms에서 콘텐츠 수정 → 저장
   689→     - / (키오스크)에서 변경 내용 반영 확인
   690→     - Polling 인터벌(30초) 내 자동 갱신 확인
   691→     - ETag 기반 304 응답 동작 확인
   692→
   693→□ 6. RBAC 권한 적용 확인
   694→     - super_admin: 모든 기능 접근 가능
   695→     - admin: 콘텐츠/도서/공지/설정 편집 가능, 관리자 계정 관리 불가
   696→     - viewer: 읽기 전용, 편집 버튼 비활성화
   697→     - 권한 없는 API 직접 호출 → 403 응답
   698→
   699→□ 7. 반응형 레이아웃 확인 (모든 /admin/* 페이지)
   700→     - 375px: 모바일 레이아웃 (사이드바 숨김)
   701→     - 768px: 태블릿 레이아웃 (사이드바 축소)
   702→     - 1024px: 소형 데스크톱 (사이드바 확장)
   703→     - 1920px: 풀 HD (최적 레이아웃)
   704→
   705→□ 8. Audit 로깅 동작 확인
   706→     - CMS 콘텐츠 수정 → AuditLog 레코드 생성
   707→     - 도서 정보 수정 → AuditLog 레코드 생성
   708→     - 관리자 계정 생성 → AuditLog 레코드 생성
   709→     - /admin/audit에서 로그 조회 가능
   710→
   711→□ 9. 이미지 업로드 동작 확인
   712→     - 정상 이미지 업로드 → /public/uploads/cms/ 저장
   713→     - CmsImage DB 레코드 생성 확인
   714→     - 파일 크기 초과 → 에러 메시지
   715→     - 허용되지 않은 MIME → 에러 메시지
   716→
   717→□ 10. 통계 대시보드 동작 확인
   718→     - 대출/반납 추이 차트 렌더링
   719→     - 카테고리 분포 차트 렌더링
   720→     - 데이터 없을 시 빈 상태 UI 표시

   722→□ 11. 콘솔 오류 0건 확인

   729→     - TypeScript 타입 오류 0건

   751→### 6.3 알려진 제약 (대시보드 확장)
   752→
   753→```
   754→1. JWT는 localStorage에 저장 (XSS 공격에 취약, httpOnly 쿠키 미사용)
   755→   → 차기 개선: httpOnly + Secure 쿠키 전환 검토
   756→
   757→2. 이미지 업로드는 로컬 파일시스템에 저장 (클라우드 스토리지 미사용)
   758→   → 차기 개선: S3/OSS 클라우드 스토리지 연동 검토
   759→
   760→3. RBAC 권한은 코드에 정적 정의 (동적 권한 할당 미지원)
   761→   → 차기 개선: 관리자 UI에서 권한 편집 기능 검토
   762→
   763→4. CMS 폴링은 클라이언트 기반 (WebSocket 미사용)
   764→   → 차기 개선: Server-Sent Events 또는 WebSocket 도입 검토
   765→
   766→5. 통계 데이터는 실시간 집계 (별도 집계 테이블 미사용)
   767→   → 차기 개선: DashboardStat 테이블로 배치 집계 검토
   768→
   769→6. 다국어 미지원 (관리자 UI 한국어만)
   770→   → 차기 개선: i18n 도입 검토
   771→
   772→7. 관리자 대시보드와 키오스크가 동일 포트(3000)에서 실행
   773→   → 분리 불가, Next.js 라우팅으로 경로 분리만 가능
   774→
   775→8. 감사 로그 보관 기간 미설정 (무한 증가 가능)
