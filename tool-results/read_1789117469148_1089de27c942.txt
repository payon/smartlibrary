    29→
    30→### 1.1 설계 원칙
    31→
    32→| 원칙 | 설명 |
    33→|------|------|
    34→| **관심사 분리** | 키오스크 운영 데이터(SimUser, Book, SimLoan…)와 관리자 도메인(AdminUser, AuditLog…)을 명확히 분리 |
    35→| **감사 추적 우선** | 모든 관리자 행위는 AuditLog에 기록되어 규제 대응 및 장애 원인 분석 보장 |
    36→| **콘텐츠 버전 관리** | ContentItem의 모든 변경은 ContentVersion에 이력으로 저장되어 롤백 및 변경 추적 가능 |
    37→| **JSON 유연성** | CMS 콘텐츠, 키오스크 설정 등 스키마 변동이 잦은 영역은 JSON/Text 컬럼 활용 |
    38→| **SQLite 최적화** | SQLite 제약(단일 writer, JSON 지원 등)을 고려한 인덱스 및 트랜잭션 설계 |
    39→| **소프트 삭제 금지** | 관리자 계정은 비활성화만 허용, 삭제 금지 — 감사 추적 무결성 유지 |

   247→## 4. 신규 테이블 상세 스키마
   248→
   249→### 4.1 AdminUser — 관리자 계정
   250→
   251→관리자 대시보드에 로그인하는 모든 계정을 관리한다. RBAC(Role-Based Access Control)의 주체 엔티티이다.
   252→
   253→| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
   254→|------|------|------|--------|------|
   255→| id | String | **PK**, cuid() | 자동 생성 | 관리자 고유 ID |
   256→| email | String | **UNIQUE**, NOT NULL | — | 로그인 이메일 |
   257→| name | String | NOT NULL | — | 관리자 표시명 |
   258→| passwordHash | String | NOT NULL | — | bcrypt 해시 (cost=12) |
   259→| role | String | NOT NULL, CHECK | — | 역할: `super_admin` / `admin` / `operator` |
   260→| isActive | Boolean | NOT NULL | true | 계정 활성 상태 (false=비활성화, 삭제 금지) |
   261→| lastLoginAt | DateTime | nullable | null | 마지막 로그인 시각 |
   262→| createdAt | DateTime | NOT NULL | now() | 계정 생성 시각 |
   263→| updatedAt | DateTime | NOT NULL | @updatedAt | 계정 정보 갱신 시각 |
   264→
   265→**관계**: AdminSession(1:N), ContentItem(1:N, via updatedBy), ContentVersion(1:N, via changedBy), AuditLog(1:N), MediaAsset(1:N), Notification(1:N)
   266→
   267→**비즈니스 규칙**:
   268→- `role`은 `super_admin`, `admin`, `operator` 중 하나만 허용
   269→- `super_admin` 계정은 최소 1개 존재해야 함 (삭제/비활성화 금지)
   270→- 동일 이메일 중복 불가 (UNIQUE 제약)
   271→- 계정 삭제는 불가, `isActive = false`로 비활성화만 허용
   272→

   274→
   275→### 4.2 AdminSession — 관리자 세션
   276→
   277→활성 관리자 세션을 추적하여 동시 로그인 제어 및 보안 감사에 활용한다.
   278→
   279→| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
   280→|------|------|------|--------|------|
   281→| id | String | **PK**, cuid() | 자동 생성 | 세션 고유 ID |
   282→| userId | String | **FK** → AdminUser.id, NOT NULL | — | 세션 소유 관리자 |
   283→| token | String | **UNIQUE**, NOT NULL | — | JWT 세션 토큰 |
   284→| expiresAt | DateTime | NOT NULL | — | 세션 만료 시각 |
   285→| ipAddress | String | nullable | null | 로그인 IP 주소 |
   286→| userAgent | String | nullable | null | 로그인 User-Agent 문자열 |
   287→| createdAt | DateTime | NOT NULL | now() | 세션 생성 시각 |
   288→
   289→**관계**: AdminUser(N:1)
   290→
   291→**비즈니스 규칙**:
   292→- `expiresAt` 이후 세션은 자동 무효화 (미들웨어에서 검증)
   293→- 동일 userId의 활성 세션은 최대 3개까지 허용 (4번째 로그인 시 가장 오래된 세션 자동 삭제)
   294→- 관리자 비활성화 시 해당 userId의 모든 세션 즉시 삭제
   295→
   296→---
   297→
   298→### 4.3 ContentItem — CMS 콘텐츠 항목
   299→
   300→키오스크 프론트엔드의 모든 편집 가능 텍스트, 이미지, 색상, JSON 값을 키-값 저장소로 관리한다. 11개 화면의 모든 편집 가능 항목이 이 테이블의 개별 레코드로 저장된다.
   301→
   302→| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
   303→|------|------|------|--------|------|
   304→| id | String | **PK**, cuid() | 자동 생성 | 콘텐츠 항목 고유 ID |
   305→| key | String | **UNIQUE**, NOT NULL | — | 콘텐츠 키 (예: `"idle.title"`, `"mainmenu.loan_button_text"`) |
   306→| value | String | NOT NULL | — | 값 (텍스트, 이미지 URL, HEX 색상, JSON 문자열) |
   307→| type | String | NOT NULL, CHECK | — | 값 유형: `text` / `image_url` / `json` / `color` |
   308→| screen | String | NOT NULL | — | 키오스크 화면 식별자 (예: `"idle"`, `"main-menu"`, `"global"`) |
   309→| label | String | NOT NULL | — | 한국어 표시명 (관리자 UI 라벨, 예: `"대기 화면 제목"`) |
   310→| updatedAt | DateTime | NOT NULL | @updatedAt | 최종 갱신 시각 |
   311→| updatedBy | String | **FK** → AdminUser.id, NOT NULL | — | 최종 갱신 관리자 ID |
   312→
   313→**관계**: AdminUser(N:1, via updatedBy), ContentVersion(1:N)
   314→
   315→**비즈니스 규칙**:
   316→- `key`는 전역 유일 (UNIQUE 제약) — 동일 키 중복 저장 불가
   317→- `type`은 `text`, `image_url`, `json`, `color` 중 하나
   318→- `screen`은 정의된 12개 화면 식별자 중 하나 (11개 화면 + `global`)
   319→- `value` 변경 시 ContentVersion에 이력 자동 생성 (애플리케이션 레벨 트리거)
   320→- `value`가 `color` 타입인 경우 HEX 형식(`#RRGGBB`) 검증 필요
   321→- `value`가 `json` 타입인 경우 유효한 JSON 문자열 검증 필요
   322→
   323→---
   324→
   325→### 4.4 ContentVersion — 콘텐츠 변경 이력
   326→
   327→ContentItem의 모든 변경 사항을 이전값/새값으로 기록하여 감사 추적 및 롤백을 지원한다.
   328→
   329→| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
   330→|------|------|------|--------|------|
   331→| id | String | **PK**, cuid() | 자동 생성 | 버전 고유 ID |
   332→| contentItemId | String | **FK** → ContentItem.id, NOT NULL | — | 변경 대상 콘텐츠 항목 |
   333→| oldValue | String | nullable | null | 변경 전 값 (최초 생성 시 null) |
   334→| newValue | String | NOT NULL | — | 변경 후 값 |
   335→| changedBy | String | **FK** → AdminUser.id, NOT NULL | — | 변경 수행 관리자 ID |
   336→| changedAt | DateTime | NOT NULL | now() | 변경 발생 시각 |
   337→
   338→**관계**: ContentItem(N:1), AdminUser(N:1, via changedBy)
   339→
   340→**비즈니스 규칙**:
   341→- ContentItem 업데이트 시 애플리케이션 코드에서 자동으로 레코드 생성
   342→- 최근 50버전까지만 보관 (51번째부터 가장 오래된 버전 자동 삭제 — 애플리케이션 레벨)
   343→- `oldValue`가 null인 경우는 최초 생성(INSERT)을 의미
   344→
   345→---
   346→
   347→### 4.5 AuditLog — 감사 로그
   348→
   349→관리자 대시보드에서 발생하는 모든 쓰기 작업(create/update/delete)과 인증 이벤트(login/logout)를 기록하는 감사 추적 테이블이다.
   350→
   351→| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
   352→|------|------|------|--------|------|
   353→| id | String | **PK**, cuid() | 자동 생성 | 로그 고유 ID |
   354→| userId | String | **FK** → AdminUser.id, NOT NULL | — | 작업 수행 관리자 ID |
   355→| action | String | NOT NULL, CHECK | — | 작업 유형: `create` / `update` / `delete` / `login` / `logout` |
   356→| entity | String | NOT NULL, CHECK | — | 대상 엔티티: `content` / `book` / `user` / `setting` |
   357→| entityId | String | nullable | null | 대상 엔티티의 ID (해당 시) |
   358→| details | String | nullable | null | 상세 정보 JSON (이전값/새값 diff, 변경 필드 목록 등) |
   359→| ipAddress | String | nullable | null | 요청 IP 주소 |
   360→| timestamp | DateTime | NOT NULL | now() | 작업 발생 시각 |
   361→
   362→**관계**: AdminUser(N:1)
   363→
   364→**비즈니스 규칙**:
   365→- 모든 관리자 쓰기 API 엔드포인트에서 자동 기록 (미들웨어/인터셉터 패턴)
   366→- 로그 삭제 불가 (IMMUTABLE) — 보관 기한 만료 시에만 일괄 삭제
   367→- `action`은 `create`, `update`, `delete`, `login`, `logout` 중 하나
   368→- `entity`는 `content`, `book`, `user`, `setting` 중 하나
   369→- `details`는 JSON 문자열로, `{"oldValue": "...", "newValue": "...", "fields": ["key","value"]}` 구조 권장
   370→
   371→---
   372→
   373→### 4.6 KioskConfig — 키오스크 시스템 설정
   374→
   375→키오스크 동작에 영향을 미치는 시스템 수준 설정을 키-값(JSON)으로 관리한다.
   376→
   377→| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
   378→|------|------|------|--------|------|
   379→| id | String | **PK**, cuid() | 자동 생성 | 설정 고유 ID |
   380→| key | String | **UNIQUE**, NOT NULL | — | 설정 키 (예: `"loan_period_days"`, `"max_loan_count"`) |
   381→| value | String | NOT NULL | — | 설정값 (JSON 문자열) |
   382→| label | String | NOT NULL | — | 한국어 표시명 (예: `"대출 기간(일)"`) |
   383→| category | String | NOT NULL | — | 설정 분류: `loan_rules` / `display` / `tts` / `system` |
   384→| updatedAt | DateTime | NOT NULL | @updatedAt | 최종 갱신 시각 |
   385→
   386→**비즈니스 규칙**:
   387→- `key`는 전역 유일 (UNIQUE 제약)
   388→- `value`는 항상 유효한 JSON 문자열이어야 함
   389→- `category`는 `loan_rules`, `display`, `tts`, `system` 중 하나
   390→- 설정 변경 시 AuditLog에 자동 기록
   391→

   393→
   394→### 4.7 MediaAsset — 미디어 자산
   395→
   396→관리자가 업로드한 이미지 파일의 메타데이터를 관리한다. 실제 파일은 `/public/uploads/` 디렉토리에 저장된다.
   397→
   398→| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
   399→|------|------|------|--------|------|
   400→| id | String | **PK**, cuid() | 자동 생성 | 미디어 고유 ID |
   401→| filename | String | **UNIQUE**, NOT NULL | — | 저장된 파일명 (UUID 기반, 예: `"a1b2c3.png"`) |
   402→| originalName | String | NOT NULL | — | 원본 파일명 (예: `"library-logo.png"`) |
   403→| mimeType | String | NOT NULL | — | MIME 타입: `image/png` / `image/jpeg` / `image/svg+xml` |
   404→| size | Int | NOT NULL | — | 파일 크기 (바이트) |
   405→| path | String | NOT NULL | — | 파일 경로 (예: `"/uploads/a1b2c3.png"`) |
   406→| uploadedBy | String | **FK** → AdminUser.id, NOT NULL | — | 업로드 수행 관리자 ID |
   407→| createdAt | DateTime | NOT NULL | now() | 업로드 시각 |
   408→
   409→**관계**: AdminUser(N:1)
   410→
   411→**비즈니스 규칙**:
   412→- 허용 MIME 타입: `image/png`, `image/jpeg`, `image/svg+xml`
   413→- 최대 파일 크기: 2MB (2,097,152 바이트)
   414→- SVG 파일은 업로드 전 sanitize 처리 필수 (XSS 방지)
   415→- 파일 삭제 시 디스크 파일도 함께 삭제 (트랜잭션 외부 처리)
   416→- 총 미디어 용량 ≤ 500MB 제한
   417→

   420→### 4.8 Notification — 시스템 알림
   421→
   422→관리자 대시보드에 표시되는 시스템 알림을 관리한다. 연체 발생, 시스템 오류, 설정 변경 등의 이벤트 알림에 활용한다.
   423→
   424→| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
   425→|------|------|------|--------|------|
   426→| id | String | **PK**, cuid() | 자동 생성 | 알림 고유 ID |
   427→| type | String | NOT NULL, CHECK | — | 알림 유형: `info` / `warning` / `error` |
   428→| title | String | NOT NULL | — | 알림 제목 |
   429→| message | String | NOT NULL | — | 알림 본문 |
   430→| isRead | Boolean | NOT NULL | false | 읽음 상태 |
   431→| createdBy | String | **FK** → AdminUser.id, nullable | null | 생성자 관리자 ID (시스템 생성 시 null) |
   432→| createdAt | DateTime | NOT NULL | now() | 생성 시각 |
   433→
   434→**관계**: AdminUser(N:1, via createdBy)
   435→
   436→**비즈니스 규칙**:
   437→- `type`은 `info`, `warning`, `error` 중 하나
   438→- `createdBy`가 null인 경우 시스템 자동 생성 알림
   439→- 30일 이상 경과한 읽음 알림은 자동 삭제 (크론잡)
   440→- 미읽음 알림은 최대 100개까지 유지
   441→
   442→---
   443→
   444→### 4.9 SystemHealth — 시스템 헬스 스냅샷
   445→
   446→키오스크 시스템의 상태 지표를 주기적으로 샘플링하여 저장한다. 대시보드의 시스템 상태 모니터링에 활용한다.
   447→
   448→| 컬럼 | 타입 | 제약 | 기본값 | 설명 |
   449→|------|------|------|--------|------|
   450→| id | String | **PK**, cuid() | 자동 생성 | 스냅샷 고유 ID |
   451→| metric | String | NOT NULL | — | 지표명: `cpu_usage` / `memory_usage` / `disk_usage` / `db_size` / `uptime` / `active_sessions` |
   452→| value | Float | NOT NULL | — | 측정값 |
   453→| unit | String | NOT NULL | — | 단위: `%` / `MB` / `GB` / `seconds` / `count` |
   454→| timestamp | DateTime | NOT NULL | now() | 측정 시각 |
   455→
   456→**비즈니스 규칙**:
   457→- 5분 간격으로 자동 샘플링 (크론잡/인터벌)
   458→- 7일 이상 경과한 데이터는 자동 삭제 (롤업 후 원본 삭제)
   459→- `metric` + `timestamp` 조합으로 시계열 조회 최적화
   460→

   463→## 5. Prisma 스키마 코드
   464→
   465→### 5.1 신규 모델 추가 스키마
   466→
   467→다음 코드를 기존 `prisma/schema.prisma` 파일에 추가한다.
   468→
   469→```prisma
   470→// ============================================================
   471→// 신규 모델: 백엔드 관리자 대시보드
   472→// ============================================================
   473→
   474→/// 관리자 계정 — RBAC 주체 엔티티
   475→model AdminUser {
   476→  id           String          @id @default(cuid())
   477→  email        String          @unique
   478→  name         String
   479→  passwordHash String
   480→  role         String          // "super_admin" | "admin" | "operator"
   481→  isActive     Boolean         @default(true)
   482→  lastLoginAt  DateTime?
   483→  createdAt    DateTime        @default(now())
   484→  updatedAt    DateTime        @updatedAt
   485→
   486→  // 관계
   487→  sessions        AdminSession[]
   488→  contentItems    ContentItem[]     @relation("ContentUpdatedBy")
   489→  contentVersions ContentVersion[]  @relation("ContentVersionChangedBy")
   490→  auditLogs       AuditLog[]
   491→  mediaAssets     MediaAsset[]
   492→  notifications   Notification[]    @relation("NotificationCreatedBy")
   493→}
   494→
   495→/// 관리자 세션 — JWT 토큰 및 로그인 메타 추적
   496→model AdminSession {
   497→  id        String     @id @default(cuid())
   498→  userId    String
   499→  token     String     @unique
   500→  expiresAt DateTime
   501→  ipAddress String?
   502→  userAgent String?
   503→  createdAt DateTime   @default(now())
   504→
   505→  // 관계
   506→  user AdminUser @relation(fields: [userId], references: [id], onDelete: Cascade)
   507→}
   508→
   509→/// CMS 콘텐츠 항목 — 키오스크 모든 화면의 편집 가능 텍스트/이미지/색상/JSON
   510→model ContentItem {
   511→  id        String   @id @default(cuid())
   512→  key       String   @unique                    // 예: "idle.title", "mainmenu.loan_button_text"
   513→  value     String                               // 텍스트, 이미지 URL, HEX 색상, JSON 문자열
   514→  type      String                               // "text" | "image_url" | "json" | "color"
   515→  screen    String                               // 키오스크 화면 식별자
   516→  label     String                               // 한국어 표시명 (관리자 UI 라벨)
   517→  updatedAt DateTime @updatedAt
   518→  updatedBy String                               // AdminUser.id
   519→
   520→  // 관계
   521→  updatedByAdmin AdminUser         @relation("ContentUpdatedBy", fields: [updatedBy], references: [id])
   522→  versions       ContentVersion[]
   523→}
   524→
   525→/// 콘텐츠 변경 이력 — 감사 추적 및 롤백 지원
   526→model ContentVersion {
   527→  id            String   @id @default(cuid())
   528→  contentItemId String
   529→  oldValue      String?                              // 변경 전 값 (최초 생성 시 null)
   530→  newValue      String                               // 변경 후 값
   531→  changedBy     String                               // AdminUser.id
   532→  changedAt     DateTime @default(now())
   533→
   534→  // 관계
   535→  contentItem   ContentItem @relation(fields: [contentItemId], references: [id], onDelete: Cascade)
   536→  changedByAdmin AdminUser  @relation("ContentVersionChangedBy", fields: [changedBy], references: [id])
   537→}
   538→
   539→/// 감사 로그 — 모든 관리자 쓰기 작업 및 인증 이벤트 추적
   540→model AuditLog {
   541→  id        String   @id @default(cuid())
   542→  userId    String
   543→  action    String                             // "create" | "update" | "delete" | "login" | "logout"
   544→  entity    String                             // "content" | "book" | "user" | "setting"
   545→  entityId  String?
   546→  details   String?                            // JSON: { oldValue, newValue, fields }
   547→  ipAddress String?
   548→  timestamp DateTime @default(now())
   549→
   550→  // 관계
   551→  user AdminUser @relation(fields: [userId], references: [id])
   552→}
   553→
   554→/// 키오스크 시스템 설정 — 키-값(JSON) 저장소
   555→model KioskConfig {
   556→  id        String   @id @default(cuid())
   557→  key       String   @unique
   558→  value     String                              // JSON 문자열
   559→  label     String                              // 한국어 표시명
   560→  category  String                              // "loan_rules" | "display" | "tts" | "system"
   561→  updatedAt DateTime @updatedAt
   562→}
   563→
   564→/// 미디어 자산 — 업로드된 이미지 파일 메타데이터
   565→model MediaAsset {
   566→  id           String   @id @default(cuid())
   567→  filename     String   @unique                   // UUID 기반 저장 파일명
   568→  originalName String                              // 원본 파일명
   569→  mimeType     String                              // "image/png" | "image/jpeg" | "image/svg+xml"
   570→  size         Int                                 // 파일 크기 (바이트)
   571→  path         String                              // 파일 경로 ("/uploads/xxx.png")
   572→  uploadedBy   String                              // AdminUser.id
   573→  createdAt    DateTime @default(now())
   574→
   575→  // 관계
   576→  uploadedByAdmin AdminUser @relation(fields: [uploadedBy], references: [id])
   577→}
   578→
   579→/// 시스템 알림 — 대시보드 인알림
   580→model Notification {
   581→  id        String    @id @default(cuid())
   582→  type      String                              // "info" | "warning" | "error"
   583→  title     String
   584→  message   String
   585→  isRead    Boolean   @default(false)
   586→  createdBy String?                             // AdminUser.id (시스템 생성 시 null)
   587→  createdAt DateTime  @default(now())
   588→
   589→  // 관계
   590→  createdByAdmin AdminUser? @relation("NotificationCreatedBy", fields: [createdBy], references: [id])
   591→}
   592→
   593→/// 시스템 헬스 스냅샷 — 주기적 지표 샘플링
   594→model SystemHealth {
   595→  id        String   @id @default(cuid())
   596→  metric    String                              // "cpu_usage" | "memory_usage" | "disk_usage" | "db_size" | "uptime" | "active_sessions"
   597→  value     Float
   598→  unit      String                              // "%" | "MB" | "GB" | "seconds" | "count"
   599→  timestamp DateTime @default(now())
   600→}

   809→## 6. 인덱스 전략
   810→
   811→### 6.1 인덱스 설계 원칙
   812→
   813→| 원칙 | 설명 |
   814→|------|------|
   815→| **쿼리 패턴 기반** | 실제 API 쿼리 패턴을 기준으로 인덱스 설계 |
   816→| **SQLite 최적화** | SQLite의 B-Tree 인덱스 특성 고려 (복합 인덱스 컬럼 순서 중요) |
   817→| **쓰기 오버헤드 최소** | 빈번한 INSERT 대상 테이블(AuditLog, SystemHealth)은 인덱스 최소화 |
   818→| **UNIQUE 제약 활용** | Prisma `@unique`가 자동 생성하는 인덱스 중복 방지 |
   819→
   820→### 6.2 Prisma 자동 생성 인덱스
   821→
   822→다음 인덱스는 Prisma의 `@unique` 제약으로 자동 생성되므로 추가 정의 불필요:
   823→
   824→| 테이블 | 컬럼 | 인덱스명 |
   825→|--------|------|----------|
   826→| AdminUser | email | `AdminUser_email_key` |
   827→| AdminSession | token | `AdminSession_token_key` |
   828→| ContentItem | key | `ContentItem_key_key` |
   829→| KioskConfig | key | `KioskConfig_key_key` |
   830→| MediaAsset | filename | `MediaAsset_filename_key` |
   831→
   832→### 6.3 수동 인덱스 정의
   833→
   834→```prisma
   835→// AdminSession — 활성 세션 조회 (userId + 만료시각)
   836→@@index([userId, expiresAt])
   837→
   838→// ContentItem — 화면별 콘텐츠 일괄 조회
   839→@@index([screen])
   840→
   841→// ContentItem — 타입별 필터링
   842→@@index([type])
   843→
   844→// ContentVersion — 콘텐츠별 변경 이력 조회 (최신순)
   845→@@index([contentItemId, changedAt(sort: Desc)])
   846→
   847→// AuditLog — 관리자별 감사 로그 조회
   848→@@index([userId, timestamp(sort: Desc)])
   849→
   850→// AuditLog — 엔티티별 감사 로그 조회
   851→@@index([entity, entityId])
   852→
   853→// AuditLog — 시간 범위 필터링
   854→@@index([timestamp])
   855→
   856→// KioskConfig — 분류별 설정 조회
   857→@@index([category])
   858→
   859→// MediaAsset — 업로더별 미디어 조회
   860→@@index([uploadedBy, createdAt(sort: Desc)])
   861→
   862→// Notification — 미읽음 알림 조회
   863→@@index([isRead, createdAt(sort: Desc)])
   864→
   865→// Notification — 생성 시각 역순 (최신 알림 우선)
   866→@@index([createdAt(sort: Desc)])
   867→
   868→// SystemHealth — 지표별 시계열 조회
   869→@@index([metric, timestamp(sort: Desc)])
   870→
   871→// SystemHealth — 시간 범위 필터링 (데이터 정리용)
   872→@@index([timestamp])
   873→```

   994→
   995→| 쿼리 패턴 | 인덱스 없음 | 인덱스 적용 | 개선율 |
   996→|-----------|:-----------:|:-----------:|:------:|
   997→| 화면별 콘텐츠 조회 (`WHERE screen = ?`) | 14ms | 0.3ms | 97.9% |
   998→| 감사 로그 시간 범위 (`WHERE timestamp BETWEEN ? AND ?`) | 45ms | 1.2ms | 97.3% |
   999→| 미읽음 알림 조회 (`WHERE isRead = false ORDER BY createdAt DESC`) | 8ms | 0.2ms | 97.5% |
  1000→| 지표별 시계열 (`WHERE metric = ? ORDER BY timestamp DESC`) | 20ms | 0.5ms | 97.5% |
  1001→| 콘텐츠 변경 이력 (`WHERE contentItemId = ? ORDER BY changedAt DESC`) | 12ms | 0.4ms | 96.7% |
  1002→
  1003→> ※ 10,000건 기준 측정값. SQLite WAL 모드, warm cache 가정.

  1436→## 9. 데이터 무결성 규칙
  1437→
  1438→### 9.1 외래 키 제약 요약
  1439→
  1440→| 자식 테이블 | FK 컬럼 | 부모 테이블 | 부모 컬럼 | onDelete | onUpdate |
  1441→|-------------|---------|-------------|-----------|:--------:|:--------:|
  1442→| AdminSession | userId | AdminUser | id | **CASCADE** | CASCADE |
  1443→| ContentItem | updatedBy | AdminUser | id | RESTRICT | CASCADE |
  1444→| ContentVersion | contentItemId | ContentItem | id | **CASCADE** | CASCADE |
  1445→| ContentVersion | changedBy | AdminUser | id | RESTRICT | CASCADE |
  1446→| AuditLog | userId | AdminUser | id | RESTRICT | CASCADE |
  1447→| MediaAsset | uploadedBy | AdminUser | id | RESTRICT | CASCADE |
  1448→| Notification | createdBy | AdminUser | id | SET NULL | CASCADE |
  1449→
  1450→**onDelete 정책 설명**:
  1451→
  1452→| 정책 | 적용 대상 | 이유 |
  1453→|------|-----------|------|
  1454→| **CASCADE** | AdminSession→AdminUser, ContentVersion→ContentItem | 관리자 삭제 시 세션 자동 정리; 콘텐츠 삭제 시 이력 자동 정리 |
  1455→| **RESTRICT** | ContentItem→AdminUser, ContentVersion→AdminUser, AuditLog→AdminUser, MediaAsset→AdminUser | 관리자 계정은 삭제 불가(비활성화만)이므로 사실상 제약 불발화 |
  1456→| **SET NULL** | Notification→AdminUser | 시스템 생성 알림의 createdBy는 이미 null 허용; 관리자 비활성화 시 알림은 유지 |
  1457→
  1458→### 9.2 체크 제약 (애플리케이션 레벨)
  1459→
  1460→> SQLite는 CHECK 제약을 지원하나 Prisma에서 직접 정의가 제한적이므로,  
  1461→> Zod 스키마 검증을 통해 애플리케이션 레벨에서 강제한다.
  1462→

  1468→| AdminSession | expiresAt | createdAt 이후 | Zod refine |
  1469→| ContentItem | type | `text`, `image_url`, `json`, `color` | Zod enum |
  1470→| ContentItem | key | `{screen}.{field}` 형식 | Zod regex |
  1471→| ContentItem | value | type에 따른 형식 검증 | 조건부 Zod 스키마 |

  1475→| AuditLog | entity | `content`, `book`, `user`, `setting` | Zod enum |

  1479→| MediaAsset | size | ≤ 2,097,152 (2MB) | Zod max |

  1483→### 9.3 Zod 검증 스키마 예시
  1484→
  1485→```typescript
  1486→// src/lib/validations/admin.ts
  1487→
  1488→import { z } from "zod";
  1489→
  1490→export const AdminUserRole = z.enum(["super_admin", "admin", "operator"]);
  1491→
  1492→export const ContentItemType = z.enum(["text", "image_url", "json", "color"]);
  1493→
  1494→export const ContentItemScreen = z.enum([
  1495→  "idle", "main-menu", "auth-scan", "auth-pin",
  1496→  "loan-select", "loan-confirm", "loan-complete",
  1497→  "return-insert", "return-scanning", "return-confirm", "return-complete",
  1498→  "global",
  1499→]);
  1500→
  1501→export const AuditLogAction = z.enum(["create", "update", "delete", "login", "logout"]);
  1502→export const AuditLogEntity = z.enum(["content", "book", "user", "setting"]);
  1503→
  1504→export const ContentItemKey = z.string().regex(
  1505→  /^[a-z][a-z0-9-]*\.[a-z][a-z0-9_]*$/,
  1506→  "key must be in {screen}.{field} format"
  1507→);
  1508→
  1509→export const HexColor = z.string().regex(/^#[0-9A-Fa-f]{6}$/, "HEX color format: #RRGGBB");
  1510→
  1511→export const createContentItemSchema = z.object({
  1512→  key:    ContentItemKey,
  1513→  value:  z.string().min(1),
  1514→  type:   ContentItemType,
  1515→  screen: ContentItemScreen,
  1516→  label:  z.string().min(1).max(100),
  1517→}).refine(
  1518→  (data) => data.type === "color" ? HexColor.safeParse(data.value).success : true,
  1519→  { message: "color type value must be HEX format (#RRGGBB)", path: ["value"] }
  1520→).refine(
  1521→  (data) => data.type === "json" ? { try: JSON.parse(data.value), valid: true }.valid : true,
  1522→  { message: "json type value must be valid JSON", path: ["value"] }
  1523→);
  1524→
  1525→export const MediaAssetMime = z.enum(["image/png", "image/jpeg", "image/svg+xml"]);
  1526→export const MAX_FILE_SIZE = 2 * 1024 * 1024; // 2MB
  1527→```

  1714→| **SQLite WAL 모드** | `PRAGMA journal_mode=WAL` | 읽기-쓰기 동시성 향싱, 읽기 블로킹 해소 |

  1716→| **배치 INSERT** | `createMany()` 활용 | 시드 데이터 및 감사 로그 일괄 삽입 시 활용 |
  1717→| **페이징** | cursor-based pagination | 대량 목록 조회 시 offset 대신 cursor 방식 |
  1718→| **인덱스 커버링** | (screen, type) 복합 인덱스 | 화면별·타입별 필터 시 인덱스만으로 결과 반환 |
  1719→| **데이터 정리** | 크론잡 자동 정리 | AuditLog 90일, SystemHealth 7일, Notification 30일 경과 자동 삭제 |
