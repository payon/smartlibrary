    27→    27→## 1. 시스템 전체 구조
    28→    28→
    29→    29→### 1.1 아키텍처 개요
    30→    30→
    31→    31→백엔드 관리자 대시보드는 기존 스마트 도서관 키오스크 시뮬레이터(Next.js 16, port 3000) 내에 **`/admin/*` 경로로 통합**되는 모듈이다. 별도 프로세스나 포트 없이 동일한 SQLite 데이터베이스와 Prisma 클라이언트를 공유하며, 관리자가 변경한 CMS 콘텐츠가 키오스크 프론트엔드에 폴링 기반 실시간 동기화로 반영되는 구조를 갖는다.

   345→   345→### 3.1 콘텐츠 편집 흐름 (Admin UI → API → DB → Cache → Kiosk)
   346→   346→
   347→   347→```
   348→   348→┌──────────────┐    ① PATCH 요청    ┌───────────────────────┐    ② Prisma WRITE    ┌──────────────┐
   349→   349→│  Admin UI    │ ─────────────────► │ /api/admin/content/   │ ───────────────────► │  CmsContent  │
   350→   350→│  (편집 폼)   │                    │ :key                   │                      │  (SQLite)    │
   351→   351→│              │ ◄──────────────── │                        │                      └──────┬───────┘
   352→   352→│  ⑥ 토스트    │    ③ 200 OK       │  ③' AuditLog 기록     │                             │
   353→   353→│  "저장됨"    │                    │      + 캐시 갱신       │                             │
   354→   354→└──────────────┘                    └───────────────────────┘                             │
   355→   355→                                                                                          │ ④ content-cache
   356→   356→                                                                                          │   version++
   357→   357→                                                                                          ▼
   358→   358→                                                                                 ┌──────────────────┐
   359→   359→                                                                                 │ Content Cache    │
   360→   360→                                                                                 │ (인메모리)        │
   361→   361→                                                                                 │ version: N       │
   362→   362→                                                                                 │ data: Map<key,  │
   363→   363→                                                                                 │   value>         │
   364→   364→                                                                                 └────────┬─────────┘
   365→   365→                                                                                          │
   366→   366→                                                    ⑤ 키오스크 폴링 (30s)                  │
   367→   367→┌──────────────┐    ⑧ Re-render   ┌───────────────┐    ⑦ Zustand set()    ┌───────▼────────┐
   368→   368→│  Kiosk UI    │ ◄────────────── │  useCmsStore   │ ◄────────────────── │  GET /api/content│
   369→   369→│  (IdleScreen │                  │  (Zustand)     │    ⑥ JSON + ETag    │  (If-None-Match)│
   370→   370→│   etc.)      │                  └───────────────┘                      └────────────────┘
   371→   371→└──────────────┘
   372→   372→```
   373→   373→
   374→   374→| 단계 | 설명 | 지연 |
   375→   375→|------|------|------|
   376→   376→| ① | 관리자가 편집 폼에서 값 변경 후 "저장" 클릭 | 사용자 액션 |
   377→   377→| ② | Admin API가 Prisma로 `CmsContent` 테이블에 UPSERT | ~5ms |
   378→   378→| ③ | API가 `AuditLog`에 변경 전후값 기록 + 응답 200 OK | ~3ms |
   379→   379→| ③' | `content-cache.ts` 인메모리 캐시 갱신 + version++ | ~1ms |
   380→   380→| ④ | 캐시 버전 카운터 증분, ETag 값 변경 | ~0ms |
   381→   381→| ⑤ | 키오스크 프론트엔드가 30초 간격으로 `GET /api/content` 폴링 | ≤30s |
   382→   382→| ⑥ | 서버가 ETag 비교, 변경 시 200 + 새 데이터, 미변경 시 304 | ~2ms |
   383→   383→| ⑦ | Zustand `useCmsStore.setCmsContent()` 호출로 전역 상태 갱신 | ~1ms |
   384→   384→| ⑧ | React가 상태 변경 감지, 해당 CMS 값을 사용하는 컴포넌트만 Re-render | ~16ms |
   385→   385→
   386→   386→**총 전파 지연**: CMS 저장 후 **≤30초** 내 키오스크 화면에 반영 (ETag 기반 최적화 시 변경 즉시 응답)

   389→   389→

   399→   399→│              │    (httpOnly)     │                        │
   400→   400→└──────────────┘                    └───────────────────────┘
   401→   401→       │

   403→   403→       ▼
   404→   404→┌──────────────────────────────────────────────────────────────────────────────┐
   405→   405→│  Request: GET /api/admin/content                                            │

   407→   407→│                                                                             │
   408→   408→│  ┌─────────┐    ⑥ JWT 검증     ┌──────────────┐    ⑦ 권한 확인   ┌────────┐│
   409→   409→│  │Middleware│ ──────────────► │  admin-auth.ts│ ─────────────► │ RBAC   ││
   410→   410→│  │  (Next)  │                  │  verifyJWT()  │                │ Table  ││
   411→   411→│  └─────────┘                    └──────────────┘                └────────┘│
   412→   412→│       │                                                              │     │
   413→   413→│       │  ⑧ 응답                                        ⑨ 허용/거부  │     │
   414→   414→│       ▼                                                              ▼     │

   417→   417→│  └───────────────┘                                          │ Forbidden   ││
